# 2026-08-14 學習日記

## 今天做了什麼
接續昨天中斷的工作，把「多利」（每日 cloud routine 排程）的 Duoli Mailer 寄信全掛問題徹底查清楚並修好。一開始只是想改個環境變數，結果一路挖出 7 個疊在一起的根因：
1. Worker 收件人格式只吃陣列，但排程 prompt 寫成字串，被 400 打回
2. 7 支寄信排程的 Cloud environment 一直停在系統預設「Default」，根本沒切到早就建好的「Duoli Mailer」環境，token 沒被注入
3. Duoli Mailer 環境的 Network access 設成「Trusted」，把自訂的 Worker 網域擋在外面
4. Worker 端的 token 跟 claude.ai 環境變數版本不同步，回 401
5. Resend 用共用測試網域寄信，CC 給阿分（非帳號本人）被 403 拒收——後來發現帳號其實早就驗證過 `mail.beyond-ans.com` 這個子網域，換過去就解決了
6. 防重複 log 的 `git push` 一律 403——一開始猜是 GitHub App 權限問題，後來去 GitHub 網頁查證發現完全沒裝任何 Claude 的 App，判斷錯誤，真正原因是 claude.ai 平台規定「cloud session 的 git push 只能推回自己的 working branch」，最後改成幫 Worker 加一個 Cloudflare KV 端點取代 git，7 支排程全部改寫
7. 順手把新聞、AI創業案例、書籍摘要三支排程從每週改成每天，補上 CC

## 補充：Podcast 影片工作流與剪紙精選

今天把《不標準答案》的影片分流從「有素材就直接做」改成先判讀、再由我確認。新規則是：說「做 IG 內容」時，走 15 秒直式節目預告；說「圖卡／輪播圖」才走靜態 `cards`；說「剪紙風／節目精選」走剪紙風節目精選。丟真人素材或標記「真人」時，小查先判讀是否適合 `shorts-pipeline`；標記「訪談」時，先判讀是否適合 `talking-head-recut`。它只能提出建議、理由、預計交付物與缺少素材，等我回覆「確認製作」才可以開始剪。

新增 `podcast-teaser-video` Skill，解決第一版 S3EP2 預告只有封面慢推鏡加音檔的問題。之後預告固定以逐字稿中的主句和時間碼為錨點，先讓我從 10 句候選金句選 5 句，再指定 1 句做預告主句。影片要有 3 段明確重點卡、進度資訊與可驗證的動態，不准再用一張靜態封面撐滿 15 秒。星期天流程也補上了「選預告主句」和「節目預告」步驟，但不會自行上傳。

剪紙風影片的問題更明確：原本動畫在第 6 秒就完成，後面只剩音檔，留存自然往下掉。這次把規則改成長於 15 秒的精選平均每 1.5 至 2 秒要有新的視覺節點，同一完整構圖最多留 3 至 4 秒。新節點不一定要換全新背景，可以是新物件進場、物件關係改變、資料逐步出現或場景切換。完整場景切換預設用右往左翻書，長度 0.35 至 0.55 秒，有紙張厚度、陰影和小回彈；同場景內只做物件動作，不要每個小動作都翻頁。

素材策略也定下來：素材庫放私有 Google Drive，不進公開 repo。建立背景、人物、物件、地圖資料、疊件和集數資料夾，並建立 `asset-manifest.csv`。每支片約 60 至 80% 使用可重用紙片，20 至 40% 新增與本集觀點有關的主物件，才不會每集長得一樣，也不會把圖像額度燒光。所有可動素材必須是透明背景的 RGBA PNG，不可把文字或背景烙在一起；背景維持獨立完整底圖，是唯一例外。若生成工具先給綠幕，必須去背並檢查紙邊沒有殘綠才可入庫。

## 這次遇到的問題與解法

1. GitHub CLI 一直顯示 keyring 裡的 token 無效，即使 GitHub 網頁裝置授權顯示完成。先確認不是帳號或網路問題，因為 `gh api user` 能讀到 `CharlesWang1221`，但 `gh pr` 的 GraphQL 仍回 401。最後以我同意的方式改用 GitHub CLI 本機設定檔保存 token，避開故障的 Windows keyring。這是權宜作法，token 沒有進 repo，但之後要找時間修 Windows keyring，改回較安全的保存方式。
2. 工作區混有影片原始檔、渲染輸出、多利文件和其他未完成 Skill，不能直接 `git add -A`。只提交影片路由、節目預告、星期天串接、剪紙流程與素材模板這 5 個檔案。
3. 原本的 `agent/creator-os` 分支比 `main` 多了多利和日記等舊提交，直接開 PR 會把不相干歷史一起送去。做法是先建立精準 commit，再從最新 `main` 建 `agent/podcast-video-workflows` 乾淨分支，只 cherry-pick 這一次的 commit。
4. cherry-pick 時發現 `main` 已刪除舊版 `paper-collage-video`，與本次更新形成 modify/delete 衝突。因為新版剪紙流程正是這次要保留的功能，選擇重新加入新版 Skill，再完成 cherry-pick。
5. 第一次用 PowerShell 組 Git 補丁時，中文在 Git index 變成問號，幸好在 commit 前的 staged diff 看出來。撤掉錯誤暫存，改用 UTF-8 補丁重新暫存並跑 whitespace check，才提交。
