## YouTube OAuth 授權排錯

### 遇到什麼問題

換到 Mac 後，`tools/youtube-upload.js` 缺少 `tools/client_secret.json` 與 `tools/youtube-token.json`，因此無法使用 YouTube 自動上傳。

一開始照文件進 Google Cloud Console 下載憑證，卻一直看到「需要額外存取權」。當時最容易誤判成「還沒登入」，實際檢查頁面右上角帳號後，才發現瀏覽器裡的 2 個帳號都沒有 `podcast-tools-501708` 專案權限。光貼同一個專案網址，不會改變登入身分，也不代表帳號真的有權限。

### 怎麼查

沒有繼續在登入頁打轉，而是先查本機下載資料夾。結果找到 `client_secret.json.json`，這才是剛下載完成的檔案，只是 Chrome 因副檔名重複，多補了一次 `.json`。

接著只檢查 JSON 結構，不輸出秘密內容。確認它是 Desktop OAuth Client、`project_id` 正確、包含 Client ID、Client Secret 與 `http://localhost` redirect URI，再複製成工具預期的 `tools/client_secret.json`。

### 排除過程

憑證放好後仍沒看到授權畫面，原因不是 Google 壞掉，而是原本的上傳腳本必須先收到 `--episode`，而且找到該集的 `youtube.txt` 與 `.mp4`，才會走到 OAuth。為了避免「只想授權，卻意外開始上傳影片」，這次沒有硬跑完整上傳流程，而是單獨產生只有 `youtube.upload` scope 的授權網址。

Google 授權完成後跳到 `http://localhost`，Chrome 顯示 `ERR_CONNECTION_REFUSED`。這個畫面看起來像失敗，其實授權碼已經放在網址列。工具沒有啟動 localhost callback server，所以瀏覽器當然連不上；真正要做的是取回一次性 code，再向 Google Token API 交換 token。

第一次交換 token 時又遇到 `getaddrinfo ENOTFOUND oauth2.googleapis.com`。這不是授權碼失效，而是執行環境的網路沙箱擋住 DNS。允許該次 Google Token API 連線後重跑，成功產生 `tools/youtube-token.json`，內含 access token 與 refresh token。

### 最後怎麼驗證

- `client_secret.json` 的專案 ID 與 OAuth 類型正確。
- `youtube-token.json` 同時有 access token、refresh token，scope 僅限 `youtube.upload`。
- 兩個檔案權限都是 `600`，只有本機使用者能讀。
- 兩個檔案都被 `.gitignore` 排除，沒有進入公開 repo。
- 授權過程沒有上傳任何影片。

### 這次學到的

OAuth 排錯要把 4 層拆開看：Cloud 專案權限、Client 憑證、瀏覽器使用者授權、token 交換。只盯著「有沒有登入」會在錯的樓層繞圈。

看到 localhost 拒絕連線也別急著判定失敗。先看網址有沒有 `code`，再判斷是 OAuth 被拒絕，還是根本沒有人在本機接 callback。這次真正的 bug 不是 Google 授權失敗，是舊腳本把「取得授權」綁死在「準備上傳某一集」後面，讓第一次設定很難單獨驗證。
