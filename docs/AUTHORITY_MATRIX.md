# 授權矩陣

本表切開「老查叫我處理」與「老查授權我改變外部世界」。各職位（見 `docs/CEO_CONTROL_TOWER.md`）預設主動做內部、可逆且不公開的工作；涉及品牌、平台、費用、帳號、私密資料與不可逆變更時，遵守更高門檻。

| 動作 | 可直接做 | 需要老查明確指示 | 另需硬性放行或證據 |
| --- | --- | --- | --- |
| 讀 repo、分析素材、查現有狀態、建立任務卡 | 是 | 否 | 遵守隱私與 repo 公開規則 |
| 寫內部草稿、任務文件、計畫、技術修正 | 使用者已要求該成果時 | 範圍會改變產品方向或大量重構時 | 不覆蓋既有成品；保留版本 |
| 生成圖像、影片草稿、預覽或 QC | 使用者已要求製作且素材可用時 | 真人／訪談素材需先確認製作 | 視覺前讀 `DESIGN.md`；角色／隱私規則照辦 |
| 渲染正式成片 | 已有明確確認、最終規格與省長預算卡時 | 要新增版本、改素材用途、或預算達 L 級時 | 最終檔變動後重做鐵雄稽核 |
| 建立外部平台草稿 | 老查明確要求發布流程時 | 只是「討論」「看看」或公開範圍不明時 | 對外文案與視覺先獲品牌 `ALLOW` |
| 上傳、排程、公開發布 | 老查明確授權該發布動作時；老查對上架授權包回「可以上架」，即授權包內全部列，執行中不再逐列詢問；Firstory 先行包只含 Firstory 一列，另行授權 | 平台、時間、帳號或公開範圍不明時；包外新增、換版或改時間時 | 鐵雄稽核 PASS（雜湊與上傳檔一致）、品牌 `ALLOW`、平台成功讀回證據全部具備 |
| 修改／取消既有公開貼文或排程 | 否 | 是 | 讀回目標、影響範圍與新狀態 |
| 啟用付費服務、購買、傳送 Email、邀請協作者 | 否 | 是 | 收件人、費用、資料範圍明確 |
| 更新 A 級規則或 Skill 母版 | 可提出草案與差異 | 是 | 變更寫入 `RULE_CHANGELOG.md`；不可放私密資料 |
| 推翻鐵雄 FAIL、核准 L 級預算或使用 Sol | 否 | 是 | 理由寫入任務卡；Sol 另記入 `docs/QUOTA_LEDGER.md` |
| 同步或覆蓋 `RED` Skill | 否 | 是 | 先比對 repo 與本機差異，確認保留哪一邊 |
| 凍結違反停止線的 item（`FROZEN`） | 小查可直接做，立刻報老查 | 解除凍結只有老查能決定 | 寫明違反的條文與證據路徑；教父不得解除或繞過 |

## 兩個不可誤解的規則

- 品牌 `ALLOW` 只表示內容合品牌，不代表老查已授權發布，也不代表平台已完成。
- 平台成功讀回只證明外部動作完成，不補救未過的品牌、事實、隱私或鐵雄稽核。

## 異常時的處理

碰到登入失敗、帳號權限不足、平台欄位不一致、連接器中斷或發布時間已錯過，負責的職位停止在當前階段，經教父回報，更新任務總表與證據庫，回報「已做到哪裡、缺什麼、可選處置」。不得猜測成功、重複提交或改用另一平台掩蓋失敗。
