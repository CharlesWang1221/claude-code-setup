# 開講選段與口播判準（2026-11-02 草案）

開講正式 Skill 建立前的參考，建立 Skill 時併入其 `references/`。來源是外部「口播稿編劇」方法，核心一句話：**口播是給耳朵聽的，不是把文章縮短**。開講用的是老查、阿分的 Podcast 原音，不改寫原話，所以這套方法主要用在「挑哪一段」和「畫面怎麼補」。

## 一、這段原音能不能做開講

| 適合 | 不適合（改走解題長片或居易網誌） |
| --- | --- |
| 一段話就有一個痛點或一個反常識結論 | 要好幾層邏輯才講得通的分析 |
| 有一句聽一次就記得的原話 | 精華分散在 5 分鐘裡，剪了就斷 |
| 30–90 秒內自己講完，不靠前後文 | 依賴「剛剛阿分說的那個」才聽得懂 |
| 原音裡有具體數字、因果或時間線，資訊窗有東西可畫 | 純情緒抒發，資訊窗只能放空泛字卡 |

## 二、選段時逐項檢查

- [ ] **第一句就抓人**：前 3 秒是衝突、反問或結論，不是「對啊，然後我覺得」。第一句太弱就往後找起點，不靠加字卡硬救。
- [ ] **一段只講一件事**：中途轉話題就切在轉之前。
- [ ] **耳朵跟得上**：句子短、主詞清楚；連續三句以上的長句、專有名詞堆疊，要靠資訊窗補，補不了就換段。
- [ ] **有一句能截圖的原話**：通常放在結尾附近，大字幕放大這句。
- [ ] **句尾完整**：照 Podcast 預告音檔硬規則，用時間碼加靜音偵測找自然停頓，不為湊秒數切斷句子。
- [ ] **首尾能接**：結尾畫面或原話能回到開場，形成循環；不加片尾卡。

## 三、畫面分工（上中下三區）

- **上半資訊窗**：只畫原音裡講到的數字、因果與時間線，一個概念一格。原音沒講的不補，事實交正風查證。
- **中間大字幕**：逐句跟原音，只放大「能截圖的那一句」，全片放大不超過 2 次。
- **下半嘴型頭像**：照嘴型元件，不替原音加戲。

## 四、如果老查要另外錄口播

開講預設不寫新稿。老查若決定為某題另錄口播，稿子照以下原則寫，錄完仍是真人原聲，不用 AI 語音：

- 一口氣一句，一句不超過 15 字；逗號就是換氣點。
- 不論證，用一個真實案例代替三段道理。
- 每 30 秒至少一句能被記住的話，結尾那句最重。
- 連接詞用說話的方式（「你想喔」「講白了」「但問題是」），不用「首先、其次」。
- 寫完大聲念一遍，卡住的地方就改，並套用 `AGENTS.md` 反 AI 味規則。
