# 影華 — ASUS 軟體平台品牌宣傳片視覺系統

## 是誰、做什麼

「影華」負責把 ASUS 軟體平台（例如企業級 AI Agent 產品）做成有情緒張力、有記憶點的品牌宣傳片。跟「影碩」的分工是刻意切開的：

| | 影碩（video-explainer） | 影華（video-promo） |
| :-- | :-- | :-- |
| 內容性質 | 解釋型，證據驅動 | 品牌型，情緒/慾望驅動 |
| 目的 | 把複雜問題講清楚 | 造氣氛、留記憶點、帶 CTA |
| 結構 | VOX 五階段（故事線→章節→分鏡→微調→包裝） | Hook→Promise→Beats→Proof(可選)→Close |
| 視覺語言 | 三層(background/midground/foreground)+Camera | Apple 式極簡文字/圖形排版，留白+色塊轉場 |
| 判斷依據 | 需要圖表/架構圖/流程把技術講明白 | 不需要證據鏈，允許留白跳躍 |

兩者共用 Remotion 當渲染引擎，但視覺系統、結構骨架、判讀標準都不共用——不要把影碩的三層+Camera 規則套進影華，那是給複雜訊息圖解用的，宣傳片不需要。

## 啟動方式（跟影碩一樣——沒有固定關鍵字，但可以直接叫「影華」）

1. 使用者丟上一份文件/素材，或直接說「宣傳片」「品牌片」「影華」
2. 小查先判讀：這份內容是要**講清楚一個問題**（→ 影碩）還是要**建立品牌情緒/賣點記憶**（→ 影華）？兩者都可能牽涉 ASUS 軟體平台，差別在目的不是主題
3. 判讀完告知使用者建議走哪條，**經確認**才進入對應 SOP
4. 不是 ASUS/技術科技類、也不是品牌宣傳目的（例如純文字文案、對話類內容）就都不啟動，導去其他既有 skill

## 視覺語言：Apple 廣告式極簡

- **Typography 是主角**，不是圖表、不是插畫、不是 3D 產品鏡頭——這套系統假設沒有 CGI 產出能力，禁止依賴寫實 3D 渲染
- 大量留白，節奏靠**色塊轉場**帶動，不靠寫實場景切換或複雜視覺 layer 堆疊
- 每個 beat 只講一件事：一句話或一個詞，停留時間要夠久讓人讀完，不要塞第二個訊息進同一個 beat
- 高級感來自克制，不是靠素材堆出來的——如果一個畫面同時有標題+副標+icon+背景圖，砍到只剩一個主元素

## 結構骨架（取代 VOX 五階段）

1. **Hook** — 一句話張力/反差開場，不解釋、不鋪陳
2. **Promise** — 核心價值一句話，跟視覺基調同時定調
3. **Beats** — 3-5 個賣點，一賣點一畫面一句話，節奏一致（每個 beat 停留時間相近，不要忽快忽慢）
4. **Proof（可選）** — 有具體數據/客戶案例才插入，輕量呈現一個數字或一句引言就好，不要展開論證變成影碩的 VOX 邏輯
5. **Close** — 品牌識別 + tagline + CTA，收在一個乾淨畫面，不要疊加太多元素

## 技術路線

- **Remotion 是主引擎**（不是像影碩只當組裝層）——純文字/圖形排版動效本來就是 Remotion/CSS 的強項，跟「沒有 3D 產出能力」的限制完全吻合
- 素材來源：AI 生成圖像或現成圖庫拼接，只做背景紋理/icon 輔助，**不當主角**——主角永遠是文字和色塊構圖
- 不套用影碩的三層(background/midground/foreground)+Camera 規則
- 色彩/字體：目前沒有 ASUS 官方 VI（視覺識別）規範，**不能憑空猜色碼字體**，要拿到官方 VI 才能定案；沒拿到之前先用中性配色（黑白灰+單一強調色）打樣

## 明確的缺口（誰接手都要知道）

- 這是紙上定義，沒有真實 brief 或素材測過流程，等有真實案子再跑第一次驗證（做法可以參照影碩當年拿 Video Storyline docx 測階段 1 的方式）
- 沒有 ASUS 官方色彩/字體規範，色彩系統是暫定的中性方案，正式產出前必須換成官方 VI
- 沒有 3D/CGI 產出能力是目前的硬限制——如果之後有 Blender 資源，這套系統的「不用 CGI」假設要重新評估，不是永久規則
