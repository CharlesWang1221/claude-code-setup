# 影碩 — 影片製作總控

## 是誰、做什麼

「影碩」負責統一管理影片的內容拆解、分鏡、資產、動畫、字幕、聲音與驗收。VOX 技術解說是核心能力之一，剪紙效果是第一個獨立風格模組；未來新增風格時沿用同一套總控，不複製整個技能。

原始來源：小紅書「桂圆干啥呢」分享的公開版 Prompt v2.0，經測試套用在 ASUS Enterprise Agent Platform 的 Video Storyline 素材上驗證過流程可行。

## 風格路由

- 使用者明確說「剪紙效果」：必須完整閱讀 [references/paper-cut-effect.md](references/paper-cut-effect.md)，直接採用該模組，不得改套 VOX 紙拼貼或重新生成物件。
- ASUS／SaaS／產品技術解說：使用本檔的 VOX + Remotion 流程，視覺走乾淨科技感。
- 歷史／檔案／報導題材：未指定時可建議 VOX 紙張拼貼，但必須先說明選擇理由。
- 其他指定風格：先在 `references/` 找對應模組；找不到時回報尚未建立，不得假裝已有規格。
- 未指定風格：先依內容、平台與素材提出一個推薦，再進確認門。

新增風格時，只新增一份 `references/<style-name>.md`，並在此路由加入觸發詞與讀取規則。共用的腳本、音訊同步、輸出與 QA 留在影碩核心。

## 啟動方式

影碩有兩種啟動方式：

### 明確指定

使用者說「影碩」或指定已存在的風格模組，視為已選擇影碩；先確認輸入素材與交付範圍即可，不再詢問是否啟動影碩。

### 小查判讀

1. 使用者丟上一份文件/素材（doc、腳本、產品說明、簡報大綱）
2. 小查先判讀，用下面的判讀標準檢查是否該啟動影碩
3. 符合就告知使用者「這個適合啟動影碩」，**經使用者確認**才進入影碩的執行流程
4. 不符合（對話類／生活敘事類／純文字 SEO 文案）就不啟動；Podcast 圖卡與單集視覺回到 `podcast-publish`，SEO 才導向 `seo-article-writer`。不得假設本 repo 存在 `social-cards`。

## 判讀標準（小查用這個檢查文件是否該轉給影碩）

1. **內容範疇**：是否涉及 ASUS 產品/平台/技術（例如 Enterprise Agent Platform、雲端架構、AI Agent 工具說明），或任何技術/科技類說明主題（不限 ASUS，泛用技術科普/產品技術解說都算）
2. **內容性質**：是否屬於「解釋型」——需要用視覺證據/圖表/架構圖/流程把複雜技術講清楚,而不是對話、情感、生活敘事類內容
3. **產出形式**：最終產出是否是**影像/動畫**——純文字文案、SEO 文章不需要影碩,走既有其他 skill 就好

三個條件都符合才啟動；只符合1、2但產出是文字，不啟動。

## 執行流程：VOX + Remotion 五階段 SOP

### 前置：填項目信息
視頻主題／核心觀點／目標受眾／平台與時長／畫幅分辨率／語言敘事風格／視覺風格／旁白狀態／現有資料素材／Remotion工程狀態／最終交付分工。缺的欄位只有「會改變內容方向、畫幅、時長、視覺或交付範圍」才問，其他先列假設繼續，不要卡在問卷。

### 硬性約束（貫穿全程）
- 必須分階段執行，每到確認門必須停止，等待明確確認
- 完整分鏡確認前，不得生產正式資產或寫正片代碼
- 樣片確認前，不得批量生產或實現整片
- 每批鏡頭確認前，不得自動進入下一批
- Prompt 不是自動駕駛，是人與 AI 的製作合同

### 階段 1：故事線和腳本確認 → 確認門 A
- 資料核查：涉及歷史/人物/年份/技術數據/因果關係，優先用原始研究、檔案機構、官方資料、權威出版物,區分事實/推斷/爭議說法,不得把推斷寫成事實
- 一句話核心觀點 → 故事線（問題反差→發展→轉折→原因機制→當下意義→回應開場）→ 腳本初稿
- 完成後停止,問：「故事線和腳本是否通過,是否進入章節和旁白拆分？」

### 階段 2：章節和旁白拆分
- 每章回答一個清晰問題,標記觀眾要理解什麼/是否需要獨立鏡頭/預估占用時間
- 旁白要適合口語表達,用真人試讀或臨時 TTS 量實際口播時長,不得照搬整段旁白到畫面

### 階段 3：分鏡設計與實現
- 鎖視覺系統：背景/字體/色彩/安全區、人物照片檔案地圖圖表的處理方式、紙張顆粒撕邊陰影規則、編輯文字動畫節奏轉場語言禁用項
- **One Background, Three Layers + Camera**：Background 建立時代地點空間語境（慢速環境運動）／Midground 承載主要敘事動作（人物機器關鍵物品）／Foreground 引導視線遮擋強調結論（**可以為空,不得用底條字幕卡或裝飾框假裝前景**）／Camera 統一管理推拉平移重構圖視差,運動只服務視覺重點
- 完整分鏡：每鏡必填9項（編號章節旁白時長/認知變化與焦點/場景結構構圖/三層+Camera/資產與文字/交接入場順序/主動作與閱讀停留/退場與下一鏡連接/可行性風險）→ 確認門 B
- 三個代表鏡頭試產：選風險最高的3鏡（視覺風格風險最高/構圖關係最複雜/工程性能轉場風險最高）先驗證,不直接做整片 → 確認門 C
- 資產生產 → Remotion 分批實現（見下方工程規則）

### 階段 4：人工微調和處理
- 單鏡/批次/全片三層檢查,重點判斷：是否像編輯動畫而不是旁白加PPT、每鏡是否只有一次主要認知變化、視覺系統是否統一但不單調、卡頓來自代碼/圖片/圖層還是濾鏡

### 階段 5：配音和最後包裝
- 正式配音 → 字幕音樂音效調色 → 平台包裝 → 最終渲染交付

## 鏡頭生命週期（Shot Lifecycle：Enter → Hold → Exit）
一個鏡頭對應一次主要認知變化,不只有入場動畫：
00 上一鏡退出清理注意力 → 01 錯峰入場（主體先、輔助後、關係線最後）→ 02 主動作（一次核心變化）→ 03 閱讀停留（重要結論後停止加信息）→ 04 當前鏡退場（避免元素堆積）→ 05 與下一鏡交接（方向/遮擋/匹配物/Camera建立連續）
**核心規則**：先建立觀看順序,再讓畫面運動。動得多不等於講得清楚。
**三個禁止**：所有素材同時出現／所有圖層全程漂移／只做入場不做退場。

## 素材與動畫兩份合同
- **素材規則**：主要主體用真實視覺素材,人物/機器/建築/關鍵物品不能用簡陋方塊代替;CSS/SVG 只做信息結構(關係線/圖表/時間線/標籤),不做主體;歷史與現代要有層次差異;先列清單再生產資產
- **動畫規則**：每個動作要有敘事意圖;重要結論必須保留停頓;精確動作不要粗糙模擬(複雜機械/身體動作改用蒙太奇、特寫、狀態替換);根據內容選運動語法
- **精確動作判斷**：需要連續精確物理過程且高風險 → 不用粗糙位移假裝真實運動 → 改成特寫/姿態替代/時間省略或結果展示

## Remotion 工程規則
- 一鏡一文件(scene-01.tsx...),總 Composition 只聲明鏡頭順序與時間,不放視覺邏輯
- 內容(旁白/章節/文字)、資產(統一注冊表)、時間線、視覺參數(共享組件)四者分離
- 三種預覽：單鏡工作台(日常調位置縮放層級動畫開關)、批次預覽(最多5鏡連接方式節奏)、全片預覽(章節整體節奏轉場連續性最終輸出)
- 代理素材(低分辨率)用於開發,切正式高清素材才做 Final Render
- 每批最多5個鏡頭,完成後停止、真實預覽、人工確認,再進下一批

## 視覺風格判斷（重要——不要每次都套 VOX 紙拼貼）
「現代 VOX 紙張拼貼」只是可選預設,不是所有 VOX 動畫的硬規則：
- **企業 SaaS/產品技術類**(ASUS Enterprise Agent Platform 這類)：用三層+Camera 規則就好,視覺語言走乾淨科技感/圖示/網狀連動線,**不要**套紙拼貼質感
- **歷史/檔案/報導類題材**：才考慮啟用紙張拼貼、剪紙、報紙構圖的 VOX 預設
