# Podcast 直式預告

把 Podcast 片段做成「能停住人」的 15 秒直式預告。交付物不是靜態封面配音，而是依聲音內容換段的短片。

## 適用與界線

- 路由規則：老查說「做 IG 內容」時，預設做本 Skill 的 15 秒直式節目預告。只有明說「圖卡」、「IG 圖」、「輪播圖」或「社群圖卡」時，才改走 `cards`。
- 例外路由：說「剪紙風」或「節目精選」時，改走 `paper-collage-video` 的 Podcast 剪紙風節目精選流程；本 Skill 負責提供候選金句、音檔片段與時間碼。
- 適用：已有 MP3／WAV、封面圖，以及逐字稿或可轉寫的 Podcast 內容。
- 預設交付：9:16、15 秒、1080 × 1920、30 fps、MP4（H.264＋AAC），適用 Reels 與 Shorts。
- 不適用：要從真人錄影剪精華時，改用 `shorts-pipeline`；要只合成一張長版 Podcast 影片時，走 `podcast-publish` 的 FFmpeg 步驟。
- 不自動上傳、不公開、不把原始音檔、封面、逐字稿或本機／雲端路徑提交到公開 repo。

## 先讀的脈絡

1. 讀根目錄 `AGENTS.md` 與 `BRAND_CONTEXT.md`。
2. 視覺產出前讀根目錄 `DESIGN.md`。Podcast 社群預告預設採 IG 藍黑系：`#01101A`、`#0A2A35`、`#4AB897`、`#6DE3EA`、白色、Noto Sans TC。
3. 讀 `hyperframes` skill。既有專案的修改或渲染，依 `hyperframes-cli`；需要 GSAP 時讀 `hyperframes-keyframes`。

## 輸入

需要以下 3 項：

| 項目 | 最低要求 | 用途 |
| --- | --- | --- |
| 音檔 | MP3 或 WAV | 取得預告鉤子與最後音軌 |
| 封面 | PNG、JPG 或 WebP | 視覺主體，不得當成永遠靜止的背景 |
| 內容依據 | 可讀逐字稿、SRT，或 Whisper 結果 | 選片段與寫字卡，避免亂編 |

先用 `ffprobe` 確認音檔時長與格式。逐字稿是 DOCX 時，先確認文字沒有亂碼；若亂碼、無法讀取，改跑 Whisper 或請老查指定 15 秒時間碼。不要把低可信度轉寫當成逐字字幕。

## 預告段落由老查選

預告片段不能由 AI 自己猜。先從逐字稿提取 10 句候選金句，每句都要附：原話、講者（若可知）、起訖時間碼、為何適合當開頭。

老查先選出 5 句金句，再明確指定其中 1 句作為「節目預告主句」。該句的時間碼是剪輯錨點；從它前後裁出 12 至 18 秒的完整口語段落。若候選來源沒有可靠時間碼，先產 SRT 或請老查提供時間點，不能直接渲染。

從「星期天」呼叫時，只接收已選定的主句與時間碼，不重新提取或改選金句。

## 選片原則

1. 先找一句在前 2 秒能成立的口語鉤子，優先是具體人物、地點、衝突或反差。
2. 截取 12 至 18 秒；預設 15 秒。避免只剩寒暄、長停頓或需要前文才能懂的代名詞。
3. 依音檔把內容拆成 3 個意義段，每段約 4 至 5 秒。段名和字卡必須能對到聽得到的內容。
4. 若只有封面，字卡可做「主旨濃縮」，但不能假裝是逐字引用。若沒有可信內容依據，停下請老查指定片段或給摘要。

## 強制的畫面節奏

整支影片至少要有 3 個可辨識的資訊狀態，不接受只有封面淡入、標題出現、其餘時間停住的做法。

| 時間 | 畫面任務 | 字卡結構 |
| --- | --- | --- |
| 0 至 4.3 秒 | 第一個鉤子，封面立即可見 | `01 / 段名`＋一句大標＋一句補述 |
| 4.3 至 9.2 秒 | 第二個重點，換段清楚 | `02 / 段名`＋一句大標＋一句補述 |
| 9.2 至 15 秒 | 第三個觀點與 CTA | `03 / 段名`＋一句大標＋Podcast CTA |

- 每段只保留一個大標，不把逐字稿整段塞進畫面。
- 用右上進度條或段落碼表明目前是第幾段。
- 前一張字卡完全離場後，下一張再入場。轉場時文字不得重疊。
- 封面從第 0 格就必須可見；以安全範圍內的推拉、裁切或局部平移保持活性。禁止只有一張靜止封面撐滿 15 秒。
- 結尾維持最後訊息，不收黑、不回到空畫面。

## HyperFrames 實作

1. 在 `video-projects/<episode>-hyperframes-teaser/` 建立專案；素材放進本地 `assets/`。不要把此專案連同素材加入公開 Git。
2. 建立 `BRIEF.md`，記下片段起訖、3 個段落、平台、比例、視覺系統與素材來源類型，不寫私人絕對路徑。
3. `index.html` 用一個 `data-composition-id`、獨立影像與文字 tracks，以及已註冊的 paused GSAP timeline。
4. 為每個段落建立 `#beat-1`、`#beat-2`、`#beat-3`。以 `autoAlpha` 與 `y` 轉場，並讓同一張卡在可讀狀態至少停留 3 秒。
5. 為封面建立一段連續的安全 scale keyframes，不讓縮放後的外框越出 1080 × 1920。
6. 新增 `index.motion.json`，至少驗證：第一段立刻可見、3 段先後順序、封面在畫面內、整支片沒有凍結。
7. 在完成版面後執行：

```powershell
npm run check -- --strict --at-transitions
npx hyperframes snapshot --at 0,2.5,5,8,10,14.5
```

檢查不得有文字重疊、超出畫面、動畫靜止或對比警告。查看至少第 0 格、每段中間、兩次轉場與結尾畫面。

## 交付與渲染

先把關鍵畫面給老查看，明確說明 3 段字卡。取得確認後才以高品質渲染：

```powershell
npx hyperframes render --quality high --fps 30 --gpu --browser-gpu --strict-all --output renders\<episode>-teaser.mp4
ffprobe -v error -show_entries format=duration,size:stream=codec_type,codec_name,width,height,r_frame_rate -of json renders\<episode>-teaser.mp4
```

確認檔案存在、非 0 bytes、時長合理、解析度 1080 × 1920，且有 H.264 影像與 AAC 音軌。回報成品連結與規格。

## 這次 S3EP2 的教訓

第一次版本只做了封面慢推鏡與單一標題，使用者看起來像「一張圖片配音檔」。修正後才加入：3 段重點卡、段落碼、進度條、分段交接與 motion assertions。

未來遇到同類需求，從一開始就照這個節奏做，不要先交付靜態封面版本。
